# Support

## BLUF

- Use GitHub issues for bugs, parser fixtures, transport requests, and
  downstream feedback.
- Do not use public issues for vulnerability details.
- Include minimized packet examples only when they are safe to publish.
- Prefer current released crate versions when asking for help.
- Keep support requests focused on reproducible project behavior.

## Where To Ask

- Bugs: use the bug report issue template.
- APRS fixtures or conformance cases: use the parser fixture issue template.
- Transport adapter requests: use the transport request issue template.
- API or integration feedback: use the downstream feedback issue template.
- Security vulnerabilities: use GitHub private vulnerability reporting when
  available.

## What To Include

- Crate name and version.
- Feature flags.
- Operating system and Rust version when relevant.
- A minimized packet or input, if safe to publish.
- Expected behavior, observed behavior, and verification commands.

## What Not To Include

- Credentials, tokens, passwords, or private keys.
- Private station traffic.
- Operator names or precise private locations.
- Full production logs.
